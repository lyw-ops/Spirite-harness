# 2026-11-10 · Tier1/3/4/5 表情符号循环动效（候选，待视觉确认）

## 来由

对照近期 DeepSeek Harness 社区桌宠后，灵梦最明显的差距是四个工作档位只有一帧静态保持。
在没有新绘画、也没有视频模型的前提下，这里只用已批准像素让它们动起来。

## 做法

每张已批准的 596×596 静帧按 alpha 连通域（8 邻接，alpha > 0）**无损拆分**：与主体不相连、
不少于 100 px 的独立符号各成一层，其余全部留在 base 层。没有重绘、没有从角色身上裁块、没有补洞；
各层是批准像素的一个精确划分。

| 档位 | 独立层 | 动作 |
| --- | --- | --- |
| Tier1 | 汗滴 ×2 | 先后下滑、淡出，再从上方重新出现 |
| Tier3 | 热气 ×2 | 上升变淡，再从下方重新聚拢 |
| Tier4 | 爱心 ×2 | 反相上下浮动，大爱心每圈跳动两次 |
| Tier5 | 爱心 ×2、星星 ×3、汗滴 ×2 | 爱心浮动、星星错开闪烁、汗滴轻颤 |

角色、桌子、食物、榻榻米是同一个静止 base 层，一个像素都不动。循环 24 帧 / 10 fps / 2.4 秒。

## 证据（`build/reimu-tier-emote-loops-v1/`）

- 四个档位的 full 与 reduced 构建均经公共 CLI `plan → render → validate` 通过。
- 每个循环的第 0 帧与批准静帧 RGBA 逐像素相同；reduced motion 的 24 帧全部等于批准静帧。
- 所有发生变化的像素都落在符号外接框外扩 14 px 以内，框外变化为 0。
- 160 px 实际显示尺寸下，与静帧相差 ≥12/255 的像素数最大值：Tier1 90、Tier3 108、Tier4 255、Tier5 283。
  Tier1 的汗滴只有约 6 px 大，动效偏弱，如实记录。
- 审阅产物：`review/tiers-160px-*.gif`、`tiers-320px-*.gif`、`review/all-emote-strips.png`。

## 边界

这是符号层的动效，不是吃饭动作：嘴、手、筷子、面条都没有动。它没有接入 Consumer，没有进入任何 App，
也没有视觉批准。接入时需要新的多帧资源包、`build.py` 摘要钉、Swift 帧计划和各档位测试，
并决定这些档位离开时是否等待循环边界；这些属于后续 runtime 任务。
