# 0.8.0 keyframes and workflow closure

Date: 2026-09-19

## Decision

Close the accumulated keyframe/pulse implementation and the first
evidence-bound project workflow in one coherent local commit. Package version
0.8.0 is consistent in `pyproject.toml`, the runtime module, the installed
distribution, and the CLI. This decision does not publish a remote commit,
create a tag, upload a package, install a consumer application, or approve any
new character artwork.

The keyframe capability and workflow infrastructure have passed their required
local technical gates. The keyframe capability has also passed a fresh
consumer compatibility run against `gensokyo-codex-pets` commit
`d7394914fe2bffc5cec03d49c54d2d7285d56cd5`. Their publication gates remain
open until an exact remote ref or release identity is separately verified.

## Evidence reviewed before the commit

- `scripts/verify_m4_m5.py` passed pytest, byte-compilation, local installation
  of the core and provider packages, `pip check`, whitespace checks, and the
  complete offline M4/M5 acceptance suite. The acceptance used the installed
  0.8.0 CLI outside the repository with `PYTHONPATH` removed and no live API.
- `scripts/acceptance_m3.py` executed 54 installed-CLI calls for single-image
  and layered full/hold pipelines. All documented exit codes 0–4 were checked,
  generated sources remained byte-identical, and runtime/distribution/CLI all
  reported 0.8.0.
- `scripts/verify.py` passed the generated workflow check, diff check,
  byte-compilation, the full Harness pytest suite, and a layered source-tree
  `plan → render → validate → report` smoke path on a stable before/after source
  snapshot. Raw local receipts remain under ignored `build/verification/` and
  are not presented as remote or release evidence.
- The consumer suite ran with `SPRITE_HARNESS_BIN` pinned to this repository's
  installed 0.8.0 executable. All 125 tests passed, including the nine Harness
  integration tests that had previously been skipped when no CLI was visible.
  The consumer worktree remained clean.
- `workflow/update.py --index --check` passed against an isolated temporary Git
  index; the real index was not modified by that rehearsal.

One earlier full pytest run transiently returned generic `PROCESSING_ERROR`
instead of `ADAPTER_RESPONSE_TOO_LARGE` for the fast oversized-response test.
The targeted test then passed five consecutive runs, and later complete suites
passed. No implementation change is attributed to that non-reproduced event;
if it recurs, preserve the emitted exception type and environment before
changing the adapter boundary.
