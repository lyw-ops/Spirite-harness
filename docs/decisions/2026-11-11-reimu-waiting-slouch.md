# 2026-11-11 · 等你确认时改用托腮图（1.24 / build 26）

设计记录（`2026-11-11-reimu-dialogue-and-action-design.md` 第 3 节末尾）留着一项不需要新图的改动：观察到的状态是「等待确认」时，
她原来是静止站姿，和待机分不出来。我在回答「接着做什么」时把它列为可以直接做的一项，用户回复「做」。

## 改动

观察到的工作状态为 `needs_input` 时，画面改为已批准的托腮循环（Consumer `pets/reimu/animations/slouch`，140 帧 / 20 fps，
此前只用于「待机时偶尔托腮」和预览）。没有新图，没有新的资源包，没有改动任何批准素材。

| | |
| --- | --- |
| 何时显示 | `needs_input` 持续期间；状态一离开就回到对应画面（回到工作是矮桌吃饭，回到待机是站姿） |
| 台词 | 不变：进入时的一句（「喂，等你确认呢」等）和点击时的「那边等你确认哦」等 |
| 点击 | 第一、二、三下她留在桌前回答（托腮循环继续）；第四下的生气图不变；拖动、出错照旧 |
| 减弱动态 | 显示托腮第一帧（静止）。这是姿态不同而不是动画，所以减弱动态下也看得见 |
| 缺素材 | 托腮素材没有打包或验证失败时照旧站着，行为与 1.23 相同 |
| 烟雾过渡 | 站姿 ↔ 等确认属于跨家族，会冒烟；从工作吃饭（同在矮桌）进入等确认直接切换 |
| 进入时的眼皮小动作 | 那两下眨眼是站姿图上的帧，托腮时不再播放；托腮循环自带一次眨眼 |

实现：`PetBehavior.presentation(waitSlouchAllowed:)`（默认 false，宿主传入托腮素材是否可用），`PetBehavior.waitSlouchFrames = 140`；
节点名仍是 `needs_input`。`main.swift` 新增 `slouchAvailable`，右键菜单标题和无障碍描述会显示「双手托腮」。

## 边界

- 没有在真实屏幕上看过：本机没有录屏权限，真实的 `needs_input` 也很少出现（设计记录写的是近两个月只触发过一次）。
- 托腮图是用户此前批准的素材，但「等确认时用它」这个用法用户只是点头同意做，还没有看到效果。
- 进入等确认时她是直接出现在桌前（或经烟雾），没有画出来的坐下动作。
