# 2026-11-10 · 工作档位脸部动作候选（待视觉确认，含两处失败）

用户要求「给一些脸部动作」。四个档位的脸都画在同一张扁平图里，没有独立图层，也没有闭眼或张合嘴的备用画。
本轮尝试只用已批准像素做局部形变：在量好的小框内对原像素做连续重采样（双线性、预乘 alpha），框外一个像素不动。
与表情符号循环不同，这会在框内产生新的像素值。

| 档位 | 尝试 | 结果 |
| --- | --- | --- |
| Tier1 | 困倦眨眼（上眼睑压到下睫毛线） | **失败并移除**：刘海垂在眼睛上，形变把刘海一起压没，留下浅色方块。需要闭眼的画稿。 |
| Tier3 | 咀嚼：嘴上抬、笑眼略收 | 干净，但很轻微 |
| Tier4 | 吸面：面条在嘴和碗之间左右晃 | 干净 |
| Tier5 | 大笑：下颌上抬，嘴合拢 38% | 可用但不精致：肉串按遮挡物保留不动后，肉边缘还有少量残留色，合拢后的下缘偏软 |

证据在 `build/reimu-tier-face-loops-v1/`：八个构建经公共 CLI plan/render/validate 通过；第 0、23 帧与 reduced 全帧
等于批准静帧；变化全部落在符号区域与脸部框内。160 px 下脸部框内相差 ≥12/255 的像素数：Tier3 105、Tier4 108、Tier5 111。
审阅产物：`review/faces-320px.gif`、`faces-160px.gif`、`review/face-poses-zoom.png`。

结论：形变路线只能给出轻微动作。眨眼和真正的张合嘴需要画稿——成熟做法是像站姿眨眼那样让图像模型只改眼/嘴区域，
再用像素门限制改动范围。未接入 Consumer，未进入任何 App。
