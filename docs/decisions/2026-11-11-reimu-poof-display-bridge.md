## 为什么是烟雾，而不是画出来的起身和坐下

现在最生硬的切换是「姿势家族」之间的硬切：站姿（1254 画布、全身、人物小）↔ 坐在地上吃饭团（688）↔ 矮桌前（596、人物大、有桌子和榻榻米）。
三个家族的人物比例不同（发行跨度 245 px 对 374–454 px），所以不存在一张「同比例的中间姿态」。

2026-09-20 冻结的 `reimu-work-transitions-spec` 要求的是**画出来的角色过渡**（站 → 坐的 6–9 帧原创姿态），当时三次生成都卡在透明背景和固定场景上，
那条路至今没有可用素材；同一份规格也写明，整体平移、缩放、淡入淡出不算角色过渡，但可以作为**如实标注的 `display_bridge`** 使用。
这次做的就是后者：一团烟雾盖住角色 0.4 秒，在烟雾下面换画面。它不关闭 `REIMU-WORK-TRANSITIONS-001` 的任何门，那 30 条画出来的路线仍然是空的。

选它的理由：一套四张图通用于所有跨家族切换；不改动任何批准素材；烟雾是动画里换装、换姿势的惯用画法；
我 11 月 10 日自己否掉的「下沉—切换—回弹」研究是纯程序变换，效果太弱，烟雾至少把切换那一下完全盖住了。

## 规则

| | |
| --- | --- |
| 何时出现 | 两个**已稳定的姿势**之间家族发生变化：开工坐下、喝完茶站起来、喂饭团坐下和吃完站起、（开启待机活动时）自发吃饭和托腮 |
| 何时不出现 | 点击反应（含生气）、拖动和放下、出错；同一家族内的切换（换档位、吃饭转喝茶）照旧直接切；「减弱动态」、暂停、系统休眠时；菜单里关掉「换姿势时冒一团烟」时 |
| 时序 | 5 步 × 80 ms：旧姿势 + 起烟 → 旧姿势 + 满云 → 新姿势 + 满云 → 新姿势 + 散开 → 新姿势 + 余烟 |
| 对行为的影响 | 没有。行为模型照常立刻切换，状态、命中测试、对话框都按新姿势算；只有画面晚两步（160 ms）换图 |

规则是纯函数 `DisplayBridge.covers` / `DisplayBridge.step`（`PetBehavior.swift`），绘制在 `main.swift`：视图在角色之上再画一层烟雾，
`drawnArtwork` 只在前两步与真实画面不同。烟雾素材缺失或损坏时不出现烟雾，其余一切照旧。

## 素材

工作目录 `build/reimu-poof-bridge-v1/`。一次 Codex 图像生成，以批准的 Tier3 静帧作画风参考（她头边那两朵热气：白底、浅灰阴影、深褐细线），
画一张 2×2 的精灵表：起烟（带三道速度线）、满云、散开、余烟。交付 1192×1192 透明底，四格都不碰格线。
`poof_intake.py`：清掉 alpha 低于 24 的残留，每格居中到 596 画布；满云按比例放大 1.064 倍贴到画布边。满云对各家族轮廓的遮盖率：
站姿 97.1%，Tier2 89.6%，Tier5 96.5%，喝茶 97.7%（没盖住的是榻榻米的四角和蝴蝶结尖）。

素材包 Consumer `pets/reimu/effects/poof-v1/`，`kind: display_bridge`，候选阶段的清单 SHA-256 是 `eeb66aba…`，
`approval.motion` 写的是「候选，未经确认」；确认后已重新导出并改钉摘要（见文末）。

## 已知不足

- 烟雾盖不住的边角会提前露出新画面（榻榻米角、蝴蝶结尖），第 2 步到第 3 步之间能看到这些地方跳一下。
- 每轮对话大约出现两次（开工、喝完茶站起来），看久了可能觉得烦；所以给了菜单开关。
- 它只是把硬切盖住，没有让她真的坐下或站起来。
